# MAGIC MADE LIFE — Story Engine 설계 문서

## 0. 문서의 위치

이 문서는 MAGIC MADE LIFE 프로젝트의 최상위 설계 문서다.

`CLAUDE.md`는 실행 시 AI에게 주입되는 압축된 규칙집이며, 이 문서에서 파생된다.
설계가 바뀌면 이 문서를 먼저 수정하고, `CLAUDE.md`는 그 다음에 이 문서를 기준으로 다시 작성한다.
두 문서의 내용이 충돌할 경우 이 문서가 우선한다.

## 1. 프로젝트 개요

MAGIC MADE LIFE는 사용자가 선택한 '운명'을 매일 저녁 8시, 짧은 연재물 형태로 경험하게 하는 서비스다.

이것은 소설 생성기가 아니다. 사용자가 자신의 삶에서 선택하지 않은 다른 인생을 '읽는' 것이 아니라, 그 인생을 '살아본 것처럼' 느끼게 만드는 것이 목적이다. 이 차이가 이 프로젝트의 모든 설계 결정의 기준이다.

## 2. 시스템 구성 요소

```
[Input Layer] → [Choice Engine] → [Story Engine] → [Serialization Layer] → [Output]
                                        ↑
                            [Core Writing Principles]
                            (모든 단계에 관통 적용)
```

- **Input Layer** — 사용자가 대시보드에서 입력하는 원재료 (자유 서술, 생년월일, 이야기 시작일, 운명 조각 선택, 공유 설정)
- **Choice Engine** — 운명 조각의 선택 구조와 조합 규칙을 관리
- **Story Engine** — 실제 서사를 생성하는 핵심 로직. Core Writing Principles를 항상 따른다
- **Serialization Layer** — 하루 1화 단위로 이야기를 쪼개고 연속성을 유지
- **Output** — 사용자에게 최종 전달되는 텍스트의 형식

## 3. Choice Engine

### 3.1 선택 구조
사용자는 항상 최대 2개의 운명 조각을 선택한다.

- 무료 조각 (7종): 성공, 사랑, 가족, 행복, 명예, 지식, 불행
- 유료 경로 (6종): 경제적으로 높은 위치의 성공 / 인플루언서·연예인으로써의 성공 / 운명을 초월한 존재 / 정치인으로서의 성공 / 스포츠 선수로서의 성공(종목 선택) / 연예인과의 사랑(대상 입력)

### 3.2 조합 규칙
조각이 무료-무료, 무료-유료, 유료-유료 어떤 조합으로 선택되더라도 두 조각은 하나의 인생 안에서 원인-결과로 연결되어야 한다. 하나의 조각이 다른 조각을 압도해 배경 소품으로 전락해서는 안 된다.

### 3.3 상충 조각
서로 상반되는 조각(예: 행복/불행)이 함께 선택된 경우, 이를 인생의 서로 다른 시기 또는 서로 다른 층위(겉으로 드러난 삶 vs 내면)로 분리해 배치한다. 어느 한쪽을 삭제하거나 무시하지 않는다.

## 4. Core Writing Principles (핵심 창작 원칙)

이 프로젝트에서 기능보다 중요한 것은 문체와 전개 구조다. 아래 원칙은 Story Engine의 모든 출력에 예외 없이 적용되며, 다른 모든 설계 요소보다 우선한다.

1. **현실성** — 등장하는 모든 사건은 현실에서 실제로 일어날 법해야 한다. 초자연적 전개, 극히 희박한 우연, 비현실적 성공은 쓰지 않는다.
2. **사건 우선** — 감정은 사건의 결과로만 발생한다. 사건 없이 감정·결심·깨달음이 먼저 나오지 않는다.
3. **두 운명의 통합** — 선택된 두 조각은 하나의 인생 안에서 인과로 연결된다. 두 개의 독립된 이야기로 병렬 진행되지 않는다.
4. **우연의 역할 제한** — 우연은 '만남'만 만들 수 있다. 우연이 곧바로 성공·실패·보상 같은 '결과'를 만들면 안 된다. 만남 이후의 결과는 반드시 인물의 선택과 행동, 그에 따른 인과로 발생해야 한다.
5. **특별대우 금지** — 인물은 이유 없이 주인공을 좋아하거나 특별대우하지 않는다. 그런 감정·대우가 필요하다면, 그것을 정당화하는 사건이 먼저 있어야 한다.
6. **영화적 장면 구성** — 장면은 영화의 컷처럼 짧게 끊어 자연스럽게 이어진다. 장황한 설명·요약 대신 구체적인 순간·행동·대사로 전개한다.
7. **실제 인생의 몰입감** — 독자는 소설을 읽는 느낌이 아니라 누군가의 실제 인생 기록을 읽는 느낌을 받아야 한다. 극적 과장, 웹소설 클리셰(회귀·빙의·재벌·능력각성 등), 작위적 반전은 쓰지 않는다.

## 5. 입력 통합

- 사용자가 직접 쓴 자유 서술(300자 이상)은 인물의 배경·성격의 출발점으로 우선 반영한다. 선택된 운명 조각은 그 위에서 전개되는 사건의 방향으로 사용한다.
- 생년월일과 이야기 시작 연도는 인물의 나이·시대적 배경·사건의 개연성을 계산하는 기준이 된다. 실제 나이에 맞지 않는 시대착오적 사건은 배치하지 않는다.

## 6. 콘텐츠 안전

- 실존 인물(연예인 등)의 실명이 입력된 경우, 그 인물의 실제 사생활·명예를 훼손할 수 있는 구체적 사건은 창작하지 않는다. 관계의 감정선과 분위기만 사용한다.
- 각색이 필요한 세부 설정은 사용자에게 따로 고지하지 않고 자연스럽게 처리한다.

## 7. 연재 구조

- 하루 한 편(1화) 단위로 제공되며, 한 화는 하나의 짧은 장면 또는 하나의 사건 매듭을 완결한다.
- 각 화는 이전 화 사건의 직접적 연장선에 있어야 한다. 전날의 사건을 초기화하거나 무시하지 않는다.
- 화의 마지막은 다음 화가 궁금해지도록 여운을 남기되, 원칙 7(실제 인생의 몰입감)을 해치는 인위적 반전을 위한 반전은 만들지 않는다.

## 8. 출력 형식

- 시점: 별도 지정이 없는 한 주인공의 1인칭 또는 밀착 3인칭.
- 문체: 원칙 6(영화적 장면 구성), 원칙 7(실제 인생의 몰입감)을 항상 최우선으로 따른다.
- 분량: 한 화당 짧게 읽히는 길이를 기본으로 하며, 설명이 아닌 장면으로 채운다.
